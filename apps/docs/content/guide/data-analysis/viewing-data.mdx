Open an experiment and select **Data**. The dataset picker above the table names
the dataset you are looking at and its row count. Opening it lists every dataset
in the experiment, grouped by where it came from: the source tables, anything a
macro produced, and anything uploaded.

## Inspect a table

- Open the dataset picker to change tables. Type to filter it when an
  experiment holds many datasets.
- Select a column heading to sort ascending or descending. When the experiment
  anonymizes contributors, the contributor column sorts by the pseudonym it
  shows. On the Data tab, changing the sort column or direction returns you to
  the first page.
- Use filter chips to narrow rows by one or more columns.
- Change the rows per page or move through pages.
- Expand structured values when a cell cannot be read comfortably inline.
- Select rows to add or remove comments and quality annotations.

Question-answer columns sort numeric-looking answers by value across the whole
result, including answers already stored as text. For example, ascending order
puts `1`, `2`, `10`, `100` in that sequence. Numeric answers come first, text
answers next, and empty, whitespace-only or null answers last in either
direction. Descending reverses the numbers and text within their groups.

Numeric-looking answers in text questions also sort by value. An identifier such
as `001` sorts as one and stays displayed and exported as `001`. Signed integers
and ordinary decimals, including `.5` and `1.`, sort numerically. Very long or
very precise numbers, scientific notation such as `1e3`, separators such as
`1,000`, and units such as `12 cm` sort as text. Sorting preserves the original
answers and does not make a text column numeric for filters or charts.

A chart without aggregation that requests its rows sorted by a question-answer
column, usually its X axis, receives them in this order. Charts with aggregation
keep their existing order.

String columns from uploaded data, custom metadata and macro outputs sort as
text. Question answers copied into macro tables sort numerically by the same
rules as the original question-answer columns.

Numeric columns can open a quick table chart. This is useful for checking a
distribution while cleaning data; it is not a saved analysis.

A table with more than 200,000 rows opens on its latest 30 days: the filter bar
shows a `timestamp` filter starting 30 days before the newest measurement. It is
an ordinary filter, so change the date or remove it to see older rows.

A field from a macro, a question, custom metadata or an uploaded file can have
the same name as a column the table already has, such as `device` or `id`.
Capitals do not matter here, so `Device` clashes with `device`. The table keeps
both, and both headings show the same name. The table's own column has no tag;
the field carries a small tag saying where it came from: **Macro output**,
**Question**, **Metadata** or **Uploaded**. Hover the tag to read why it is
shown separately. For a macro output or a question, the tooltip also gives the
name the field has in exported files, such as `device_output`. Filters and chart
pickers show the same tag.

## New rows arrive on their own

You do not need to reload the page to see new measurements. While the browser
tab is visible, the Data page checks for new rows every 30 seconds and refreshes
the table when the dataset in front of you changes. After ten minutes without
mouse, keyboard or scroll input it stops checking and the line says **Paused**;
the next input catches up at once. A row that arrives this way is
tinted for a moment so you can spot it. Your sort, filters, page and selected rows
stay where they were.

The line under the page description says **Live** and when the newest data in
the dataset was received. For a macro dataset, that is when the measurement the
result came from was received, not when the macro ran. A macro's result usually
follows its measurement within half a minute. If the service that runs macros is
briefly unavailable, it is tried again for about five minutes before the row shows
an error, so a result can take that long to appear. Select the pause button
beside it to hold the table still while you work through it, and select it again
to catch up. If the page cannot reach the platform for two minutes, the line says
when it last refreshed instead. Dashboards and the visualization editor show the
same line, for the datasets their charts and tables use.

In the platform, the **Device** column uses a registered device's serial number.
For an unregistered sensor, it uses the reported name, then the client id when
the name is empty. A device-id suffix keeps sensors with the same name or
uploading phone separate, for example `Ambit (d2)` and `Ambit (d3)`. When only a
device id is available, that id is the label. Rows without a name, client id or
device id appear as `Unknown device`.

The **Device** filter uses these same labels. Its options load in name order
without case sensitivity, including devices beyond the first page. The picker
shows a loading hint while more options arrive.

Exports and Python table loads keep the registry `device` struct unchanged.
There, `device IS NULL` still finds unregistered sensors and `serial_number`
contains only the registry serial. The platform computes display labels when
it reads the data.

## Build a saved visualization

Open the experiment's **Analysis** area and choose **Visualizations**. Anyone
with **Can edit** can create a visualization, select a data table and columns,
choose a chart type, and configure its style. Saved visualizations can also be
placed on experiment dashboards.

### Sort the visualization and dashboard lists

The list of saved visualizations and the experiment's **Dashboards** list both
open with the most recently updated first. Select **Name** or **Updated** to sort
by that column, again to reverse it, and a third time to drop it. Shift-select
the other heading to add a second sort. The line above the table counts the
list, and once a sort is set, **Reset sorting** at its end returns to the
default order. The sort stays in the page URL, so a refreshed or
shared link keeps it.

The current interface supports many chart families, but a chart is only as sound
as its data configuration. Check units, missing values, grouping, contributor
anonymization, and the protocol version before interpreting a pattern.

2D histograms, 2D density plots and contour charts accept timestamp columns on
both **X** and **Y**. Choose a timestamp column to draw that axis as dates and
times, alongside a numeric column or another timestamp column. A contour chart
also needs a numeric **Z** column with varying values across the grid. Its
**Fill** and **Lines** colouring modes both support time axes.

### Add a second table

In the **Data** tab, choose the primary dataset, then open **Second table** and choose another table from the
same experiment. Choose a **Match column** that exists in both tables with the
same scalar type, then choose the time column on each table. Use measurement
time when you want readings matched by when they were taken, rather than by
when they were uploaded. Complete the match and time fields and a valid tolerance
before the chart previews or saves the change.

Set **Tolerance in minutes** to a whole number of zero or more. For each row in
the primary table, the chart takes the second table's latest reading with the
same match value, at or before that row's time and no more than the tolerance
earlier. Both time limits count. Zero requires exactly the same time. Match
values are case-sensitive. Missing match values or times do not match.
Date columns mean midnight UTC, and timestamps without a timezone also use UTC.
If second-table readings share a time, the lowest row ID wins.

Second-table columns start with `second__` in the column pickers. Select them
for axes, series, grouping, filters or style options that accept their type.
Rows without a match stay in the data, with empty second-table values. Filters
on second-table columns apply after the latest match is chosen, so they cannot
substitute an older reading. Grouping follows matching and filtering.
Choose **None** to remove the second table. Changing or removing the second
table clears its series, filters and aggregation settings. Filters, grouping,
time buckets and aggregates on primary-table columns stay in place.

Line and area charts draw a long series at screen resolution, keeping the
lowest and highest value for every pixel column, so a peak or a gap never
disappears from view. When the table holds more than 4,000 rows and the chart
plots line or area series over a time or numeric x axis, the platform reads the
table this way instead of reading its rows. Zooming in reads the visible range
in more detail, down to single rows once it holds 4,000 rows or fewer. That
applies only when the chart uses one table and has no aggregation, stacking or size column, every
series is drawn as a line or area, facets share their x axis, and the column
names start with a letter or underscore and use only ASCII letters, digits and
underscores.

A line under the chart says _Drawn at screen resolution from 553,000 rows._, for
example. _Show every point_ reads and draws the rows themselves instead, up to
the 100,000-row limit below, and _Draw at screen resolution_ switches back. The
choice is not saved with the chart. A line styled with markers draws them only
while the chart's lines hold at most 2,000 points in view between them, so a long
series shows as a clean line. The markers return as you zoom in, or everywhere
with _Show every point_.

Any other chart reads at most 100,000 rows, and tables with very wide rows can
stop it sooner. When the data holds more, a line under the chart says how much it
shows, for example _Showing 100,000 of 553,000 rows. Add a filter to see all
matching rows._ Add a filter to the visualization or to the dashboard until every
matching row fits, or export the table to work with all of it.

### Count sensors reporting per hour

Create a **Bar** chart and choose your timestamp column under **X axis**. Set its
**Bucket** to **Hour**. Under **Y axis**, choose **Distinct count** in
**Aggregate**, then choose the text column that identifies each sensor. You can
choose the aggregate before selecting a Y column.

Each bar counts the different sensor IDs within that hour. Repeated
reports from one sensor count once, and missing values do not count. An empty
string is a value and counts once. **Count** counts all non-missing values in the
selected column, including repeated sensor IDs. Both count aggregates accept
text, numeric and date columns. Their results use a numeric Y axis.

In a bar chart, if you change a text Y series to a numeric aggregate such as **Sum**, the column
selection clears. Choose a numeric column to continue.

### Compare rows in order

Under **Y axis**, the **Aggregate** menu offers **Previous value**, **Change from
previous** and **Row number**. Choose **Ordered by** to set the numeric or date
column that orders the rows from smallest to largest. Optionally choose **Per**
to restart the calculation for each sensor or other group. **Whole table** uses
one sequence for all rows.

- **Previous value** returns the selected Y column's value from the preceding row.
- **Change from previous** subtracts that value from the current value. It accepts
  numeric and date columns. Differences between dates or times are in seconds.
- **Row number** starts at 1 within each group and counts rows in the chosen order.
  Its result uses a numeric Y axis, whatever Y column you selected.

![A line chart of the seconds between sensor reports, using Change from previous on the timestamp column per sensor](/img/guide/web/ordered-aggregates-gap.webp)

Filters apply before these calculations. The first row in each group, including
the first row inside a filtered time range, has no previous value. A chart does
not draw a point for that missing value. If rows have the same ordering value,
the row ID breaks the tie when available. Otherwise their order can vary between reads.
Rows with a missing **Ordered by** value sort last and have no calculation result.
They do not take part in the sequence.

![A line chart numbering each sensor's readings in time order with Row number](/img/guide/web/ordered-aggregates-row-number.webp)

These three functions keep every row. Turn off the X **Bucket** and remove other
aggregates that combine rows before using them. Cumulative sum can share their
chart. If you later add a bucket, the editor shows an error and holds the change.
Other raw Y series stay raw. Remove the bucket to continue, or change the
row calculation to a function that combines rows.

### Choose a value at the latest or earliest row

Choose **Value at latest** or **Value at earliest** under **Aggregate**, then set
**Ordered by** to a numeric or date column. These return the selected Y value
from the row with the largest or smallest ordering value. **Per** shows the
chart's actual groups, including its X buckets, colour groups and panels. It is
read-only because these functions use the chart's grouping. Choosing either
function groups the chart by X and turns other raw Y series into **Average**.

Filters apply first. Rows with a missing ordering value do not take part. A
missing Y value at the selected row remains missing, so **Value at latest** does
not mean the latest non-empty value. If several rows tie for the latest or
earliest ordering value, the row ID breaks the tie when available. Without a row
ID, any of the tied rows' Y values may be returned.

### Split a chart into panels

In the visualization editor's **Data** tab, set **Facet (small multiples)**
to the column whose values should become panels. With shared X scales, each
column of panels shows X labels on its lowest populated panel, including a
panel above an empty grid cell. Box and violin plots keep their categories
aligned across panels; multiple series keep the same grouped positions in
each panel.

### Colour a scatter chart by a column

On a scatter chart, the **Group by** shelf colours the points by a column. When
you pick the **Column**, **Mode** is set from its type: a text or yes/no column,
or one naming a contributor or device, becomes **Categorical (per value)**, and a
numeric or date column **Continuous (gradient)**. You can change the mode
afterwards, except that a categorical column cannot use a gradient; the option
says _Continuous gradient needs a numeric or temporal column._

- **Categorical (per value)** gives every value its own colour and its own
  legend entry, with an empty value listed as "(none)". **Category colors** sets
  the colour for each of the first 50 values; the rest take their colours from
  the palette.
- **Continuous (gradient)** colours each point along a gradient, with a colour
  bar you can hide with **Show colorbar**.

### Read legends and circular charts

An outside legend has its own space beside the chart's labels and colour bar.
Cartesian charts with a secondary axis or colour bar wrap long right legend names.
If those names leave too little room for the plot, the legend moves below it.
On radar, polar, wind rose and ternary charts, long side legend names wrap. If
there is too little room beside the plot, the legend moves below it.
On radar, polar, wind rose and ternary charts, a top or bottom legend scrolls
when its entries exceed the available legend space. The 64-pixel band keeps the
plot visible when there are many entries. Scrolling those entries requires a
pointer; Plotly legends do not support keyboard interaction. The chart title stays
above the outer axis labels. A top legend also scrolls within its own space when a
chart title is set. Long radar axis names wrap across lines. Polar charts show
the radial axis title below the plot. A wind rose uses the translated **Frequency**
label because its radius counts observations in each direction and speed band,
rather than showing the speed itself.

When no radial tick interval is set, polar charts choose tick spacing automatically.
Polar, radar and ternary charts use fewer tick labels in smaller widgets. Explicit
tick intervals remain in use, and full-sized ternary charts keep divisions of one
tenth of the axis sum. A polar radial axis defaults to 90 degrees; an explicit
angle of zero is also respected.

### Turn a box or violin plot sideways

For a box or violin plot, choose a category column under **X axis** and a numeric
column under **Y axis** (**Variables** for violin plots). In **Style**, set **Orientation** to **Horizontal**.
The categories move to the vertical axis and the values to the horizontal axis;
the distributions and their samples stay the same. Axis titles and scale types
follow their columns. **Vertical** turns the chart upright again.

Colour groups and facets work in either orientation. **Share X axis** and
reference lines on X always refer to the horizontal axis; Y refers to the
vertical axis.

## Filter a dashboard

A filter widget narrows every chart and table on the dashboard that reads the
same data table. For a date column, choose **Last hour**, **Last 24 hours** or
**Last 7, 30 or 90 days** to save a rolling window. Each visit works out the
dates again, and the control shows them below the preset's name. The chart
editor's own filters and dashboard table filters use the same presets.

Rolling windows end at the current minute, so they can trail the clock by up
to 59 seconds. A day means 24 elapsed hours, including across daylight-saving
changes. The dates appear in your browser's local time. **Current preview**
means the range has not yet been confirmed by a successful data read.

Reopening the page or refreshing its data evaluates a new window. The existing
live-update checks also evaluate it when they fetch changed data. A dashboard
left open without a data refresh keeps the last range it read.

Choosing dates or editing either time saves a fixed custom range. Calendar
presets such as **This month** also stay fixed. Ranges saved before rolling
windows were available keep their original dates; choose the preset again to
make one roll.

A custom _between_ filter needs both _From_ and _To_, with _From_ as
the start of the range and _To_ as the end. When a filter's value can't be
used, the widget says what to fix under its fields: _Add a To value, or clear
From._, _Add a From value, or clear To._, _Swap From and To, or change one of
them._ or _This value can't be used as a filter._ A _between_ filter on numbers
or dates also outlines both fields in red. The filter doesn't filter anything
until then. Each chart and table on that data table says so in a line under it,
for example _1 filter skipped: Signal_, naming the filter by its title, or by its
column when it has none, and shows its rows without that filter. The dashboard
editor shows the same reason for a filter's default value. Clear both fields to
remove the filter on purpose.
